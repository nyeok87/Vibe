# 주간 일정·업무계획 종합·배포 웹앱 (시제품)

PRD: `../PRD_주간일정종합배포_웹앱.md`

부서가 HWPX 일정 파일을 올리면, 최종 담당자가 상부 공통일정과 함께 종합하고 화면에서 다듬은 뒤 HWPX 최종본으로 내려받고 전 부서에 배포한다.

> ⚠ 시제품입니다. Vercel·Supabase는 외부 인터넷 클라우드이므로 **실제 부대 일정·인원 정보는 입력하지 말고 가상 데이터로만** 검증하십시오.

## 바로 실행 (내 PC, Supabase 없이)

```bash
npm install
npm run dev
```

http://localhost:3000 접속 → 공용 접속코드 `1234` → (관리자) 비밀번호 `admin1234`

- Supabase 환경변수가 없으면 데이터가 `.data/` 폴더에 저장됩니다. 처음부터 다시 하려면 서버를 끄고 `.data` 폴더를 지운 뒤 다시 실행합니다.
- 초기 접속코드·비밀번호는 `.env.local`의 `ACCESS_CODE`, `ADMIN_PASSWORD`로 바꿀 수 있습니다(첫 실행 때만 적용, 이후에는 [설정] 화면에서 변경).

## 시연용 가상 HWPX

```bash
npm run samples            # samples/2026-11-02/ 에 생성 (다른 주차: npm run samples 2026-11-09)
```

| 파일 | 용도 |
|---|---|
| `기획과.hwpx` … `교육과.hwpx` (9개) | 부서 제출 (재정과는 일부러 없음 → 미제출 표시) |
| `인사과.hwpx` | 요일을 일부러 틀리게 적어 경고 표시 확인 |
| `작전과_수정본.hwpx` | 수정 시나리오: 장소 변경·일정 삭제·일정 추가 |
| `상부_공통일정.hwpx` | 열 이름이 다른 상부 양식(일자/주요 일정/참석 대상) 자동 해석 확인 |
| `_빈_제출양식.hwpx` | 빈 제출양식 |
| `_최종본_예시.hwpx` | 위 파일을 종합한 최종본(작전과 수정본 반영, "※ 변경사항" 포함) — 한글 열기·인쇄 확인용 |

### 시연 순서 (AC1~AC8)
1. 접속코드로 들어가 부서 선택 → 부서 HWPX 업로드 → 인식 결과 확인 → [제출] (9개 부서)
2. 관리자 로그인 → [제출 현황·종합]에서 10개 부서 상태 확인
3. `상부_공통일정.hwpx` 업로드 → 해석 결과 표 확인·수정 → [공통일정 저장]
4. [종합 만들기] → [미리보기·편집]에서 셀 직접 수정 → [HWPX 다운로드] → [배포]
5. 부서 화면 [배포본 열람]에서 읽기 전용 열람·인쇄
6. 작전과로 `작전과_수정본.hwpx` 다시 제출 → 현황판 「수정됨」 → [종합 만들기] (작전과만 갱신, 다른 부서의 직접 수정은 유지) → [다시 배포] → 표 아래 "※ 변경사항"

## Vercel + Supabase 배포

1. Supabase 새 프로젝트 → SQL Editor에서 `supabase/schema.sql` 실행 (테이블, RLS, 비공개 버킷 `files` 생성)
2. Supabase Project Settings > API 에서 `Project URL`, `service_role` 키 확인
3. 이 폴더를 GitHub 저장소로 올리고 Vercel에서 Import
4. Vercel 환경변수: `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `SESSION_SECRET`(긴 임의 문자열), `ACCESS_CODE`, `ADMIN_PASSWORD`
5. Deploy

service role 키는 서버에서만 쓰이고 브라우저로 나가지 않습니다. 브라우저(anon) 접근은 RLS로 모두 막혀 있습니다.

## 구성

| 경로 | 내용 |
|---|---|
| `src/lib/hwpx/parse.ts` | HWPX 해석 (ZIP → `Contents/section*.xml` 표·문단). 머리글 텍스트로 표 식별 |
| `src/lib/hwpx/build.ts` | HWPX 생성 (A4 세로, 함초롬바탕/돋움, 머리글 행 반복, 쪽 번호 하단 가운데) |
| `src/lib/hwpx/templates.ts` | 부서 제출양식 / 최종본 양식 |
| `src/lib/repo.ts` | 제출·종합(부분 갱신)·변경 비교·배포 로직 |
| `src/lib/db.ts` | 저장소 (Supabase 또는 로컬 `.data`) |
| `src/app/...` | 화면 S0~S7, API |

## PRD와 다르게 구현한 점

- **변경 각주**: PRD 8장의 대체 방안을 적용해, 한글 각주 객체 대신 각 구역 표 바로 아래에 "※ 변경사항" 문단으로 기록합니다. 변경된 행의 내용 앞에는 `※` 표시가 붙습니다. (각주 객체는 한글에서 직접 검증하지 못해 시제품에서는 넣지 않았습니다)
- `submissions` 테이블에 해석 결과를 담는 `parsed_data`(jsonb) 열을 추가했습니다. `weeks`에 `last_composed_at`도 추가했습니다.
- 마감 시각은 "대상 주차 바로 전 주의 지정 요일·시각"으로 계산합니다.

## 확인이 필요한 점

생성 HWPX는 독립 파서(@rhwp/core)로 열어 표·병합·머리글 반복·쪽 나눔을 확인했지만, **한컴오피스 한글 본 프로그램에서는 아직 열어 보지 않았습니다.** 한글에서 최종본·제출양식을 열어 양식이 깨지지 않는지, A4로 인쇄되는지(AC5) 확인해 주십시오. 실제 한글에서 저장한 제출양식의 해석도 같은 방식으로 확인이 필요합니다.
